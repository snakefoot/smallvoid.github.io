This layout: Displays the page title and optional description. Filters by Windows version, category, or both. Lists matching posts alphabetically by title. Uses the same logic for every group-page. The default layout assumes you have a _layouts/default.html layout. If your theme provides the default layout, you can generally use that instead. 3. Thin group-pages Now each group-page only needs front matter. For windows/winxp.md: yaml --- layout: article-group title: Windows XP permalink: /windows/winxp/ description: Articles relevant to Windows XP. version_filter: WinXP --- For windows/winxp-performance.md: yaml --- layout: article-group title: Windows XP Performance permalink: /windows/winxp/performance/ description: Performance tweaks and optimizations for Windows XP. version_filter: WinXP category_filter: Tweak/Performance --- For windows/performance.md: yaml --- layout: article-group title: All Performance Articles permalink: /windows/performance/ category_filter: Tweak/Performance --- That's it. You can create as many group-pages as you want without copying the filtering logic. 4. One important detail about categories If your article front matter uses: yaml categories: - Tweak/Performance make sure that post.categories contains the exact value Tweak/Performance in your build. The filter uses exact matching, so Tweak and Performance as separate entries would behave differently. Also, this approach does not automatically create the group-pages. It makes each page thin, but you still create the Markdown files for each group. That's a useful trade-off for standard GitHub Pages because it avoids custom plugins. GitHub +1 For a site with dozens of Windows versions and topics, this is still manageable. If you eventually want every combination generated automatically, you can move to a custom GitHub Actions build later without changing the article metadata or the general layout design.
